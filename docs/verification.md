# 测试记录

## 设计依据

设计依据为《鲜期管家系统概要设计说明书》（XQGJ-HLD-0001，V1.3，2026-10-28），接口、数据表和目录结构分别对应第 6、7、9 章。

## 验证范围

验证使用 Python 3.12、Flask 3.1.3、SQLite 和 Node.js 24。精确开发依赖见 `requirements-lock.txt`。声明的最低 Python 为 3.11，尚未在该版本单独运行。

- Python 测试：公共校验、日期冻结、配置覆盖、参数化查询、事务提交/回滚、外键、初始化保留数据、未知数据库拒绝覆盖、统一错误响应和 32 个业务占位接口不写数据。
- Node 测试：响应解包、错误信息保留、501 识别、超时、写操作不重试及页面导航。
- 静态检查：12 个页面的四类文件、组件配置、路由注册、JSON、JavaScript 语法与本地依赖引用。
- 服务冒烟检查：实际启动本地 HTTP 服务，检查健康接口、业务 501、未知接口 404，然后停止服务。

2026-11-04 检查结果：64 项 Python 测试和 6 项 Node 测试通过；12 个页面、25 个 JavaScript 文件的静态检查通过；HTTP 冒烟检查通过。

## 尚未验证

微信开发者工具编译、WXML/WXSS 实际渲染、320 像素窄屏布局、真实 AppID 预览、手机网络、Linux/macOS 启动尚未实测。静态检查不等同于微信运行时编译。

库存生命周期、风险算法、提醒刷新、计划幂等、统计口径、业务样例与文档中的性能指标均尚未实现，因此不标为通过。开发者需要在后续实现每个模块时补充对应测试。
