# 本地部署

配置优先级为 `config/default.toml` → 未提交 Git 的 `config/local.toml` → `XQQJ_*` 环境变量。相对数据库路径始终以项目根目录为基准，与启动时的当前目录无关。

| 配置字段 | 环境变量 | 默认值 |
| --- | --- | --- |
| database | XQQJ_DATABASE | db/xqqj.db |
| host | XQQJ_HOST | 127.0.0.1 |
| port | XQQJ_PORT | 5000 |
| timezone | XQQJ_TIMEZONE | Asia/Shanghai |
| demo_date | XQQJ_DEMO_DATE | 空，使用真实日期 |

复制 `config/local.example.toml` 为 `config/local.toml` 可持久设置本机配置。删除或清空 `demo_date` 恢复真实日期。非法日期和端口在启动时直接报错，避免带错误配置继续运行。

## 真机调试

1. 将服务端 `host` 设为 `0.0.0.0`，重启服务。
2. 手机与电脑处于相互可达的局域网，用 `ipconfig` 查看电脑局域网 IPv4。
3. 修改 `miniprogram/config/index.js` 的 `baseUrl`，例如 `http://192.168.1.20:5000/api`。这只是地址格式示例，必须换成实际 IP；不要将 `0.0.0.0` 作为客户端地址。
4. 确保系统防火墙允许演示网络访问该端口，使用有权限的 AppID，在微信开发者工具中按本地 HTTP 调试要求配置网络校验。
5. 打开“我的设置 → 检查连接”；显示真实服务时间和计算日期后，再检查各页面导航。

这是本地课程演示服务，不含域名、证书、微信登录或推送接入。小程序前端不运行数据库，数据始终保存在电脑上的 SQLite 文件。

## 启停与故障

启动脚本以前台方式运行服务，按 Ctrl+C 停止。采用前台生命周期，未提供按进程名批量终止的 stop 脚本。日志默认输出至终端；如需保存，可由启动终端重定向至 `logs/`。

- 首次提示数据库缺失：执行 `python -m flask --app app init-db`（使用虚拟环境中的 Python）。
- 已有数据但提示缺失：先确认配置路径，不能把重新初始化当成数据恢复。
- 提示结构版本不兼容：保留数据库，检查版本或明确迁移，不自动重建。
- 业务接口返回 501：当前框架的预期行为，不是网络错误。
- 连接失败：检查服务状态、IP、端口、防火墙和微信调试设置。客户端不会后台自动重试。

## 手工备份与恢复

1. 停止服务，确认没有进程正在写入数据库。
2. 复制当前配置指向的数据库文件到 `db/backups/`，文件名加上日期和时间；备份不提交 Git。
3. 恢复前另行保留当前数据库，再用已确认的备份替换运行数据库。
4. 重启服务，先检查 `/api/health`，业务实现后再检查实际库存与事件。

本阶段不实现自动备份、自动恢复、样例重置或数据库修复功能。
